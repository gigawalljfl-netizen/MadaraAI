4. Nature of the Application and Data Architecture

  • 4.1. The Application is an Artificial Intelligence designed to act as an agent for productivity, automation, programming, and support for various tasks on the user's device.
  • 4.2. The Application's data architecture is based on the principle of data minimization, prioritizing processing and storage in a local environment on the user's device rather than on external servers.
  • 4.3. Local processing ensures that immediate commands and daily interactions do not leave the physical device (except what is sent to Google and Third-Party Services according to Sections 3 and 9), maintaining control under the direct custody of the user.
  • 4.4. What the Application maintains durably (Memory and Projects) is kept in three places, in this order: (i) in the Application's own internal storage on the device; (ii) optionally, mirrored in text files that the user can open and delete with any file manager, in the device's Download/Madara folder; and (iii) in the user's account on Firebase, so that Memory and Projects survive Application reinstallation (see Section 8).

5. Data Collection, Permissions, and Purposes

For the faithful execution of the duties requested by the user, the Application requires access to specific permissions of the Android operating system. Collection is strictly limited to the achievement of the Application's functionalities, including, but not limited to:

5.1. Microphone, Foreground Service, and Silence Mode Keyword

  • 5.1.1. Purpose: Capture the user's voice for conversation and keep the conversation active even with the screen off or the app in the background.
  • 5.1.2. Android requires, by the system's own policy, that a permanent notification be displayed whenever the microphone is used in the background — this notification cannot be hidden; it is an operating system transparency requirement, not an Application choice.
  • 5.1.3. Silence mode and keyword: when the user orders Madara to stop responding, the Application stops sending the microphone to Google and begins to locally listen only for the word defined by the user (default: "Madara"), to know when to resume responding. This recognition is done by the device's own speech recognition mechanism (Android's SpeechRecognizer). The Application does not record, store, or send this listening to the Developers; depending on the device and the installed mechanism, the operating system itself may process the audio locally or through a Google service — this is beyond the Developers' control. The keyword can be turned off in Settings, and in this case, return from silence only happens by touching the screen or the notification.
  • 5.1.4. Microphone audio is only sent to Google while the conversation is active and silence mode is turned off.

5.2. Accessibility (Touch screen, read screen, scroll screen, swipe, see screen)

  • 5.2.1. Purpose: Allow the AI to interact directly and mechanically with the user's graphical interface, including within other applications.
  • 5.2.2. Actions Executed: Reading text visualized on the screen, capturing screen images for the model to "see", executing touches and gestures, text typing, list scrolling, and navigation in third-party applications.
  • 5.2.3. Processing: Data processed in this category is ephemeral and intended solely for responding to the user's command in real time, not being stored persistently beyond what is necessary for the continuity of the requested task. Screen images captured for the "see screen" function are sent to Google (Section 3) and are not saved by the Developers.
  • 5.2.4. This permission is optional and only becomes active if the user manually activates the "Madara" service in Android's accessibility settings.

5.3. Notification Reading

  • 5.3.1. Purpose: Know what is playing (music/video) and read notifications when the user requests it.
  • 5.3.2. Restrictions: Access is reactive, triggered by the user's command; content is not stored on the Developers' server.
  • 5.3.3. This permission is also optional and depends on manual activation by the user in Android's settings.

5.4. SMS: Reading, Receiving, and Sending

  • 5.4.1. Permissions: READ_SMS (read previously received messages), RECEIVE_SMS (be notified when a new message arrives), and SEND_SMS (send messages).
  • 5.4.2. Receiving: when an SMS arrives, the Application announces to the user whose message it is and ASKS if they want the content to be read aloud. Content is only read after this authorization — except if the user explicitly turns on, in Settings, the option "Read SMS aloud without asking", which is turned off by default.
  • 5.4.3. Sending: the Application sends SMS only by order of the user, who defines the recipient and the text. There is an option in Settings called "Send SMS direct" (sends without opening the messaging app for review) and it can be turned off at any time; when turned off, the Application opens the messaging app with the text ready for the user to review and press send.
  • 5.4.4. Automatic responses (Section 7): the user can order Madara to respond on their own to a specific person via SMS. In this case, each sent response is logged in the event history of the Application's screen, the mode can be interrupted at any time by voice, by the "Stop autonomy" button on the notification, or by turning off the option in Settings, and there is a turn limit defined by the user.
  • 5.4.5. Storage: the Application keeps in volatile memory (only during execution, never on a server) the last received messages to allow commands like "respond to the last SMS". Messages read in the device's SMS app continue to belong to the Android system and are not copied to the Developers' server.

5.5. Contacts and Phone Calls

  • 5.5.1. Permissions: READ_CONTACTS (find someone's number by name) and CALL_PHONE (initiate the call).
  • 5.5.2. The Application only searches contacts and only initiates calls by express order of the user. The option "Call direct when I ask", in Settings, defines whether the call starts immediately or if the Android dialer is opened with the number ready for the user to confirm — the user can turn this option off whenever they want.
  • 5.5.3. Contacts are NOT sent to the Developers or copied to a server. When the user requests a call, the informed name/number is sent to Google as part of the voice or text command of that conversation (Section 3).

5.6. Location, Time, and Weather

  • 5.6.1. Permissions: ACCESS_FINE_LOCATION and ACCESS_COARSE_LOCATION.
  • 5.6.2. Purpose: respond to "where am I?", "what time is it?" with the correct time zone, and "how is the weather?" without the user needing to state the city.
  • 5.6.3. Location is obtained from the device itself (GPS/network) and can be used to (i) describe the address by reverse geocoding and (ii) consult the Open-Meteo service with the coordinates (Section 9). The Application keeps in memory only the last known position, so as not to repeatedly consult the GPS; it does not send location to the Developers.
  • 5.6.4. Without these permissions, the time remains correct (device's time zone) and the weather works when the user informs the city.

5.7. Capture of Audio Played by the Device

  • 5.7.1. Permission and technology: FOREGROUND_SERVICE_MEDIA_PROJECTION with Android 10+ AudioPlaybackCapture API.
  • 5.7.2. Purpose: allow the user to ask "what song is playing?", "transcribe what the video is saying", or "recognize the game sound" with precision — listening to the audio that the device itself is reproducing, and not the ambient sound captured by the microphone.
  • 5.7.3. Consent upon each use: Android requires that the user confirm the capture in a system window each time it is started, and consent cannot be reused — the Application discards the token as soon as the capture ends. If the user refuses, the Application honestly informs that it heard nothing and does not invent content.
  • 5.7.4. Technical limits: the Application captures at most 30 seconds at a time, only applications that the system allows to capture (media, games, and sounds without defined use), and never captures the microphone via this path. During capture, microphone transmission to Google is paused, so as not to mix the two sources.
  • 5.7.5. Captured audio is sent to Google to be interpreted (Section 3) and is not saved to a file or sent to the Developers. While capturing, Android shows the mandatory foreground service notification.

5.8. Storage and File Management (List, create, read, edit, rename, delete, copy, move, compress, decompress, search, open/reproduce, share)

  • 5.8.1. Purpose: Allow the user, through the AI, to organize, search, read, move, compress, and manage files in the device's storage, and directly open files (images, audio, text) for visualization or reproduction when requested.
  • 5.8.2. Safeguards: Access to this function is operated upon the user's demand. The AI does not scan private folders without an explicit command, and deleting/moving files is an irreversible action under the responsibility of the one who makes the command.
  • 5.8.3. Content of files read at the user's request is sent to Google for interpretation (Section 3) and is not stored by the Developers.

5.9. Programming, Projects, and Progress Logging

  • 5.9.1. Purpose: The Application writes code, creates project structures, and executes programming tasks at the user's request, registering progress step by step to know exactly where it stopped — even after closing the application, restarting the device, or reinstalling the Application.
  • 5.9.2. What is registered per project: name, description, objective, technologies, each stage performed (with date, title, status, and details), the last completed step, the next planned step, and the code files the user asks to save.
  • 5.9.3. Where it stays: in the Application's internal storage, mirrored in readable text files (PROGRESSO.md and code files) in the Download/Madara/Projetos// folder when the user grants file access, and in the user's account on Firebase (Section 8) — this means that project progress IS stored on the Developers' server, in that user's exclusive space.
  • 5.9.4. Automatic progress logging is turned on by default because it is what allows the Application to resume a project from the exact point it stopped. It can be turned off in Settings ("Save project progress step-by-step" and "Mirror projects in Download/Madara").
  • 5.9.5. The user can see everything that was registered on the Application's "Projects" screen, ask Madara to list, detail, or delete a project, or delete the files directly in the device's file manager.
  • 5.9.6. Responsibility regarding code: generated code is a suggestion produced by an AI model. Compiling, installing, publishing, or executing this code is the exclusive decision and responsibility of the user, who must review it first. The Application refuses to produce clearly malicious content (e.g., malware destined to invade third-party systems, steal credentials, or cause harm) but executes legitimate programming tasks, including creating complete applications.

5.10. Integration with Termux and Command Execution

  • 5.10.1. Permission: com.termux.permission.RUN_COMMAND, manually granted by the user in Android settings ("Additional permissions"), in addition to the user themselves needing to enable allow-external-apps=true in the ~/.termux/termux.properties file of Termux.
  • 5.10.2. Purpose: execute terminal commands in the environment of Termux installed on the device (compile, install packages, run scripts, git, etc.) when the user requests.
  • 5.10.3. Data path: the command and its arguments are delivered to Termux, which runs on the device itself; the output (stdout, stderr, and return code) returns to the Application and is sent to Google as a result of the function (Section 3). The Developers do not receive anything from this flow.
  • 5.10.4. The Application can also execute basic commands in the local Android shell (/system/bin/sh) for simple diagnostic tasks, always at the user's request and without root privileges.
  • 5.10.5. Responsibility: terminal commands can delete files, install software, and alter the system. The user is solely responsible for the commands they request and the consequences thereof. If Termux is not installed, if the permission has not been granted, or if allow-external-apps has not been enabled, the Application informs the exact reason and what to do — it does not pretend that it executed.

5.11. Music and Media Applications

  • 5.11.1. Purpose: play music, artist, album, or playlist at the user's request, using the music application they choose.
  • 5.11.2. Order of choice: (i) the application indicated in the request itself; (ii) the application marked in Settings as "music app"; (iii) Spotify, if installed; (iv) the device's default application that responds to the intention of reproduction by Android search.
  • 5.11.3. For this, the Application consults which media applications are installed on the device (Android 11+ package visibility permission). This consultation happens only on the device; the list is not sent to the Developers.
  • 5.11.4. The Application does not collect usage data from music services (Spotify, YouTube Music, etc.) — what happens within them is governed by the policies of those services.

5.12. Web Search Without Opening Browser

  • 5.12.1. Purpose: answer questions with updated information ("search now", "read this page", "Wikipedia summary") without opening a browser or leaving the conversation.
  • 5.12.2. How it works: the Device consults public services directly — DuckDuckGo (search results and instant result), Wikipedia (summaries), and Open-Meteo (weather) — and the found text is sent to Google along with the conversation for the model to formulate the response.
  • 5.12.3. Data revealed to these services: the searched terms and the device's IP address (like in any internet access). The Developers do not intermediate, register, or receive these queries.
  • 5.12.4. The Application can also open a URL in the browser, but only when the user explicitly requests it ("abrir_url").

5.13. Hardware (Camera, Flashlight, Bluetooth, Volume, Brightness)

  • 5.13.1. Purpose: Execute commands for photographic capture, flashlight activation, Bluetooth, and device adjustments upon the immediate and deliberate order of the user.
  • 5.13.2. Processing: Photos taken upon request are sent to Google when the user asks Madara to "see" the photo, and are not retained by the Developers.

5.14. Agenda, Calendar, Alarms, and Timers

  • 5.14.1. Purpose: Read and create appointments in the calendar and set alarms/timers on the device, at the user's request.
  • 5.14.2. Data Collected: Dates, times, and appointment titles entered directly by the user — they stay in the calendar of the Android system itself, not on the Developers' server.

5.15. Device Administrator

  • 5.15.1. Purpose: Allow the user to ask to lock the device screen by voice command.
  • 5.15.2. Technical limit: this permission NEVER allows unlocking the screen — Android does not offer this capability to any application, by safety design of the operating system itself.

5.16. Display over Other Applications ("Floating Eye")

  • 5.16.1. Purpose: Show a small visual indicator (Madara's eye, drawn on the device itself) over other applications while Madara is speaking, and allow a touch on it to bring Madara back from silence mode.
  • 5.16.2. This permission does not give the AI the capability to see or interact with the content of other apps — it serves only to draw the visual indicator on the screen.
  • 5.16.3. The immersive visual (Sharingan, Mangekyō, Rinnegan, Infinite Tsukuyomi, and Ten-Tails) is entirely drawn in code on the device: it does not download images, use heavy animations, or collect any data.

6. AI Memory — What is Saved Automatically

  • 6.1. For Madara to behave like someone who knows the user, the Application extracts and saves SHORT HIGHLIGHTS of the conversation without depending on the model asking to save. Extraction happens on the device, over the transcription of what the user said.
  • 6.2. Saved categories (the same used internally by the Application): humor (jokes and humor attempts), sites (links and topics the user asked to search), problems (reported difficulties), places (cited or visited locations), tastes (what the user likes or seems to like), preferences (how the user wants to be treated/served), people (cited names and relation to the user), work, plans, projects, and facts (other relevant information the user shares).
  • 6.3. What is NOT saved: conversation audio, full transcription, images, passwords, complete card numbers, third-party SMS content, and anything the user orders to forget.
  • 6.4. Where it stays: on the device (Application internal file) and, if an account was created, in the user's account on Firebase (Section 8) to survive reinstallation. None of this goes to the Developers beyond storage in the user's own account.
  • 6.5. User's total control: it is possible to ask "what do you remember", "forget this", "forget what you know about X" (removes from device and account), see statistics in Settings > "Memory state", or completely turn off automatic memory in Settings ("Save conversation highlights automatically").
  • 6.6. Memory is a short text summary: each category has an item limit, repeated items are not duplicated, and the summary injected into the conversation has a maximum size — it is not a growing file of the user's life.

7. Autonomous Conversations (with another AI or via SMS)

  • 7.1. Purpose: when the user explicitly orders ("talk to ChatGPT about X until I tell you to stop", "respond to John via SMS"), the Application continues exchanging messages on its own, without waiting for a new instruction each turn.
  • 7.2. With another AI: the conversation uses Google's text API (Section 3.3) with the user's own key; the Application informs the used model and the configured turn limit.
  • 7.3. Via SMS: the Application injects messages arriving from the combined number into the conversation and sends responses via SEND_SMS (Section 5.4).
  • 7.4. Security limits, all configurable or interruptible by the user: turn limit per conversation (Settings > Autonomy), stop by voice at any time, "Stop autonomy" button on the permanent notification, automatic termination when the connection drops, and explicit prohibition, in the model's system instruction, from impersonating the user or promising things on their behalf without an order.
  • 7.5. Responsibility: everything sent to third parties (another AI or person via SMS) during an autonomous conversation was requested by the user. The user is responsible for the sent content, the costs of their own API key, and the device's use, and can interrupt at any time.
  • 7.6. The Application does NOT initiate autonomous conversations on its own: autonomous conversation only exists after an explicit order from the user.

8. Data Processing and Storage

  • 8.1. Primacy of Local Processing: the overwhelming majority of operations, system commands, execution in applications, memory, and projects remain on the user's device itself. No behavioral, navigation, or activity data is transmitted to the Developers' servers without the user's conscious use and permission.
  • 8.2. What goes to the Developers' server (Firebase/Google Cloud): only three categories of data leave the device toward the infrastructure managed by the Developers, always restricted to the user's own account:
    • a. AI Memories: the short highlights described in Section 6 (text, category, importance, and date) — it is not a recording of the entire conversation, nor audio.
    • b. Projects: name, description, objective, technologies, progress stages, last step, next step, and the code files the user asks to save (Section 5.9).
    • c. User Account: email used to create the account and authenticate login, to keep memory and projects linked to the right person.
  • 8.3. Nothing beyond that — not voice audio, not audio captured from the device, not images sent to the model "to see", not received SMS, not contacts, not location, not command history — is stored by the Developers. This information passes through the device and Google (Section 3) as necessary to execute the command but is not saved on the Developers' own server (see Section 10 on the API Key).
  • 8.4. Security: data from item 8.2 is stored in Firebase (Google Cloud infrastructure) protected by access rules that restrict each user to read/write only their own account — no other user has access to another person's memory or projects.
  • 8.5. Application Preferences (API key, model, voice, visual theme, SMS/call options, keyword, limits) stay only on the device, in the Application's own internal storage.

9. Third-Party Services Contacted Directly by the Device

  • 9.1. Google — Gemini API (voice and text): receives the audio/text/images of the conversation, the results of executed functions, and the system instruction (which contains the memory and project summary). Governed by Google's terms (Section 3.4).
  • 9.2. DuckDuckGo: receives search terms (Section 5.12).
  • 9.3. Wikipedia: receives the consulted title/term for summaries (Section 5.12).
  • 9.4. Open-Meteo: receives geographic coordinates or city name for weather (Sections 5.6 and 5.12).
  • 9.5. Termux (application installed on the device): receives commands to execute and returns the output; runs entirely on the device (Section 5.10).
  • 9.6. Music applications installed on the device: receive the intention of reproduction by search (Section 5.11).
  • 9.7. GitHub: the Application checks if a new version is published (mandatory update check), informing only the installed version; no personal data is sent.
  • 9.8. In all cases above, contact is direct between the user's device and the service — the Developers do not operate a proxy, register, or receive this data.

10. Use of the Gemini API Key

  • 10.1. The Application does NOT possess its own API key, provisioned or managed by the Developers.
  • 10.2. Each user must obtain and configure their OWN free or paid API key directly in Google AI Studio (aistudio.google.com). The Application guides and directs the user to this site when no key is configured.
  • 10.3. This key is saved only locally on the user's device (internal storage of Android itself); it is never sent, transmitted, copied, or registered on any Developer server under any circumstances.
  • 10.4. Communication using this key happens directly between the user's device and Google's servers — the Developers do not have access to this key, do not see its content, and cannot track its use.
  • 10.5. The user is solely responsible for the custody, cost, and use of their own API key, including any charges made by Google according to the Gemini API terms of use. This includes consumption generated by autonomous conversations (Section 7), which the user can limit and interrupt.
  • 10.6. This is a deliberate Application architecture decision and is not subject to change to a shared/Developer-managed key model.
